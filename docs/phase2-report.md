# تقرير المرحلة 2 — فتح التسجيل العام واستعادة كلمة المرور

**التاريخ:** 2026-10-31  
**النطاق:** فتح التسجيل العام بشكل دائم، وتأكيد تسجيل الدخول بالبريد وكلمة المرور، وإضافة استعادة كلمة المرور عبر البريد، مع تعطيل تأكيد البريد، دون تغيير الجداول أو سياسات RLS أو البيانات الحالية، والبقاء على GitHub Pages.

---

## 1) الهدف

1. إبقاء التسجيل العام مفتوحاً بشكل دائم.
2. السماح بإنشاء الحساب والدخول فوراً دون رسالة تأكيد بريد.
3. توفير «نسيت كلمة المرور؟» وإرسال رابط استعادة فعلي.
4. عدم تعديل أو حذف أي جدول أو بيانات موجودة.
5. الحفاظ على عزل بيانات المستخدمين عبر RLS.
6. عدم إدخال أي مفتاح سري في المستودع أو الواجهة.

---

## 2) القرارات المعتمدة

- **التسجيل:** مفتوح دائماً (`disable_signup=false`).
- **تأكيد البريد:** متوقف (`mailer_autoconfirm=true`)، لأن التطبيق يعتمد على تسجيل فوري.
- **استعادة كلمة المرور:** رابط بريد عبر `resetPasswordForEmail`، وصفحة مستقلة `reset.html`.
- **عدم تغيير `detectSessionInUrl` في `store.js`:** بقي `false` لأن `share.html` يعتمد على `location.hash` لرمز المشاركة.
- **معالجة يدوية لرابط الاستعادة في `reset.js`:** لدعم مساري PKCE وImplicit دون تعارض مع صفحة المشاركة.
- **لا تغييرات على قاعدة البيانات:** لا migrations ولا تعديل RLS ولا حذف بيانات.

## 3) إعدادات Supabase

تم التغيير من لوحة التحكم ثم التحقق عبر `/auth/v1/settings`:

| الإعداد | قبل | بعد |
| --- | --- | --- |
| Allow new users to sign up | OFF (`disable_signup=true`) | **ON (`disable_signup=false`)** |
| Confirm email | ON (`mailer_autoconfirm=false`) | **OFF (`mailer_autoconfirm=true`)** |
| Email provider | ON | ON |
| Phone provider | OFF | OFF |
| Custom SMTP | OFF | OFF |

التحقق الفعلي:

```json
{"disable_signup":false,"mailer_autoconfirm":true,"external_email":true,"external_phone":false}
```

**تنبيه:** يجب إبقاء هذين الإعدادين كما هما. أي إغلاق لاحق للتسجيل أو تفعيل لتأكيد البريد سيوقف التسجيل الفوري ويعطّل تجربة المستخدم الحالية.

## 5) مسار استعادة كلمة المرور

### 5.1 من صفحة الدخول

1. يضغط المستخدم «نسيت كلمة المرور؟».
2. يُدخل البريد، ويُرسل الطلب عبر:

```js
client.auth.resetPasswordForEmail(email, { redirectTo: resetUrl });
```

3. تُعرض رسالة نجاح عامة حتى لا يُكشف ما إذا كان البريد مسجّلاً أم لا.

### 5.2 صفحة `reset.html`

تنشئ الصفحة عميلها الخاص بنفس `storageKey` (`hn.auth.session.v1`) و`flowType: 'pkce'` مع `detectSessionInUrl: false`، ثم تقرأ الرابط يدوياً:

- **مسار PKCE:** `?code=...` ← `exchangeCodeForSession(code)`.
- **مسار Implicit:** `#access_token=...&refresh_token=...&type=recovery` ← `setSession({ access_token, refresh_token })`.

بعد نجاح التحقق:

1. تُنظَّف معلمات الرابط من شريط العنوان عبر `history.replaceState`.
2. يُعرض نموذج كلمة المرور الجديدة.
3. يُحدَّث الحساب عبر `client.auth.updateUser({ password })`.
4. تُنهى الجلسات السابقة عبر `client.auth.signOut({ scope: 'global' })`.
5. تُعرض حالة النجاح مع رابط العودة لتسجيل الدخول.

### 5.3 حفظ PKCE verifier

عند طلب الاستعادة من التطبيق، يخزّن `supabase-js` الـverifier تحت `hn.auth.session.v1-code-verifier`. عدّلنا `authStorage` في `store.js` و`reset.js` ليُحفظ دائماً في `localStorage`، حتى لو فُتح رابط الاستعادة في تبويب جديد أو كان خيار «تذكرني» متوقفاً.

## 7) SMTP والمخاطر المتبقية

### 7.1 SMTP

- **Custom SMTP غير مفعّل.**
- خدمة البريد الافتراضية في Supabase محدودة ومخصّصة للاختبار، وقد لا تصل رسائل الاستعادة لكل المستخدمين أو قد تتأخر.
- طلب الاستعادة يعيد نجاحاً من جهة التطبيق حتى لو لم تصل الرسالة، وهذا سلوك مقصود لحماية خصوصية البريد.
- **للإنتاج:** Authentication → Emails → SMTP Settings، واستخدم مزوّداً موثوقاً (Resend / SendGrid / Brevo / Amazon SES) مع:
  - عنوان مرسل موثّق.
  - سجلات SPF وDKIM.
  - اختبار استعادة فعلي لبريد حقيقي.

### 7.2 مخاطر أخرى

1. **المفتاح السري `sb_secret_...`:** لم يُدوَّر بعد، ولم يُستخدم في هذه المرحلة. التطبيق يستخدم Publishable key فقط.
2. **Admin API:** المفتاح السري الحالي يعيد `401`، لذلك لا يمكن توليد روابط استعادة برمجياً من خارج اللوحة.
3. **SQL Editor:** ما زال يفشل أحياناً بـ`28P01`، وتم استخدام `psql` المباشر عبر Session Pooler.
4. **بيانات الاختبار:** لا توجد بيانات اختبار متبقية؛ تم التحقق من الأعداد.
5. **PKCE عبر المتصفحات:** الـverifier يُخزَّن في المتصفح الذي طلب الاستعادة. فتح رابط الاستعادة في متصفح أو جهاز آخر قد يعرض «رابط غير صالح». الحل الحالي: اطلب الرابط من نفس المتصفح. المسار الضمني مدعوم أيضاً في `reset.js` إذا تقرر تغيير نوع التدفق لاحقاً.
