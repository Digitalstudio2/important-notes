## 3) التغييرات على قاعدة البيانات

الملف المطبَّق على الإنتاج داخل معاملة واحدة:

```text
supabase/migrations/002_sharing_activity.sql
```

### 3.1 جدول `public.note_shares`

| العمود | النوع | ملاحظات |
| --- | --- | --- |
| `id` | `uuid` | مفتاح أساسي |
| `note_id` | `uuid` | مرتبط بـ`public.notes(id)` مع حذف متسلسل |
| `owner_id` | `uuid` | مرتبط بـ`auth.users(id)` مع حذف متسلسل |
| `token_hash` | `bytea` | SHA-256 للرمز (32 بايت)، فريد |
| `created_at` | `timestamptz` | تاريخ الإنشاء |
| `expires_at` | `timestamptz` | تاريخ الانتهاء |
| `revoked_at` | `timestamptz` | تاريخ الإلغاء إن وُجد |

- **لا يوجد عمود للرمز الصريح**؛ الرمز 64 حرفاً hex يُعاد مرة واحدة فقط عند الإنشاء.
- قيد `octet_length(token_hash) = 32` وقيد `expires_at > created_at`.
- فهرس جزئي على `(owner_id, note_id)` حيث `revoked_at is null`.
- رابط نشط واحد لكل ملاحظة: إنشاء رابط جديد يلغي القديم تلقائياً.
- RLS مفعّلة، ولا سياسة وصول مباشر؛ كل الوصول عبر RPC.
- `anon` و`authenticated` لا يملكان أي صلاحية جدولية مباشرة، و`service_role` فقط يملك `SELECT`.

### 3.2 جدول `public.activity_log`

| العمود | النوع | ملاحظات |
| --- | --- | --- |
| `id` | `bigint identity` | مفتاح أساسي |
| `user_id` | `uuid` | مرتبط بـ`auth.users(id)` مع حذف متسلسل |
| `event_type` | `text` | أحد الأنواع التسعة المسموحة |
| `entity_type` | `text` | نوع الكيان (note/share/profile) |
| `entity_id` | `uuid` | معرّف الكيان إن وُجد |
| `metadata` | `jsonb` | بيانات وصفية محدودة |
| `created_at` | `timestamptz` | وقت الحدث |

الأنواع المسموحة:

```text
account_created, login, password_changed, profile_updated,
note_created, note_updated, note_deleted, share_created, share_revoked
```

- لا يُخزَّن محتوى الملاحظة في السجل؛ فقط العنوان المختصر والتصنيف والحقول المتغيرة.
- RLS مفعّلة، وسياسة `activity_log_select_own` احتياطية، لكن لا توجد صلاحية `SELECT` جدولية لـ`anon` أو`authenticated`؛ القراءة عبر `list_activity` فقط.
- `service_role` يملك `SELECT`، والتسلسل ممنوح له.

### 3.3 الدوال (RPC)

| الدالة | المتاح لها | الوظيفة |
| --- | --- | --- |
| `create_note_share(uuid)` | `authenticated` | إنشاء رابط، يلغي النشط السابق، يعيد الرمز مرة واحدة |
| `revoke_note_share(uuid)` | `authenticated` | إلغاء الرابط النشط |
| `get_note_share_status(uuid)` | `authenticated` | حالة الرابط دون كشف الرمز |
| `get_shared_note(text)` | `anon`, `authenticated` | قراءة الملاحظة عبر الرمز، مع اسم المالك ولون صورته فقط |
| `list_activity(integer, bigint)` | `authenticated` | قراءة سجل المستخدم الحالي بترقيم تدريجي |
| `record_auth_event(text)` | `authenticated` | تسجيل `login` أو `password_changed` فقط |
| `reset_demo_notes(jsonb)` | `authenticated` | إعادة تعيين ملاحظات الحساب التجريبي السبع |
| `is_demo_account(uuid)` | داخلية | التحقق من الحساب التجريبي/المجهول |
| `record_activity(...)` | داخلية | كتابة حدث مع تجاهل الأخطاء |
| `log_note_activity()` | مشغّل | تسجيل أحداث الملاحظات |
| `log_profile_activity()` | مشغّل | تسجيل تحديث الملف الشخصي |
| `handle_new_user()` | مشغّل | إنشاء الملف الشخصي + `account_created` |

كل الدوال الحساسة `SECURITY DEFINER` مع `search_path = ''`. الدوال الداخلية لا تُنفَّذ من `anon` أو`authenticated`.

### 3.4 قيود الحساب التجريبي

- `is_demo_account` تعتمد على بريد `demo@notes.app` أو المستخدمين المجهولين.
- `record_activity` تتجاهل الحساب التجريبي، فلا يُسجَّل له أي نشاط.
- دوال المشاركة ترفض الحساب التجريبي.
- `list_activity` ترفض الحساب التجريبي.
- `reset_demo_notes` تتحقق من أن المستدعي هو الحساب التجريبي، وتستبدل ملاحظاته السبع بالقالب المرسل من الواجهة.

### 3.5 ملاحظة عن `auth.users`

لا يمكن إنشاء مشغّل جديد على `auth.users` لأن الجدول مملوك لـ`supabase_auth_admin`. لذلك:

- أُعيد تعريف `handle_new_user()` (المملوك لـ`postgres`) لتسجيل `account_created` عند إنشاء المستخدم.
- يُسجَّل `login` و`password_changed` من العميل عبر `record_auth_event` بعد نجاح العملية.

## 5) التطبيق على الإنتاج والتحقق

### 5.1 التطبيق

طُبِّق الـMigration عبر `psql` داخل معاملة واحدة مع `ON_ERROR_STOP=1`، ونجح `COMMIT`.

### 5.2 التحقق من الكتالوج

- `note_shares` و`activity_log` موجودان، وRLS مفعّلة عليهما.
- لا عمود للرمز الصريح في `note_shares`.
- لا صلاحيات جدولية مباشرة لـ`anon` أو`authenticated` على الجدولين.
- `service_role` يملك `SELECT` على `note_shares` و`activity_log`.
- صلاحيات RPC صحيحة: `get_shared_note` لـ`anon` و`authenticated`، والبقية لـ`authenticated` أو داخلية.
- مشغّلا `notes_log_activity` و`profiles_log_activity` موجودان.
- لا مشغّل جديد على `auth.users`.
- `handle_new_user` بصلاحية `SECURITY DEFINER` و`search_path = ''`.

### 5.3 التحقق السلوكي الإنتاجي

تم داخل معاملات تراجعت بالكامل:

- دورة مشاركة كاملة، ومدة 7 أيام، وتجزئة غير صريحة.
- قراءة `anon` للملاحظة المشتركة.
- منع الوصول الجدولي المباشر.
- الإلغاء والاستبدال.

| `js/share.js` | قراءة الرمز من `location.hash` فقط وعرض الملاحظة بـ`textContent` |

### 6.2 رابط المشاركة

```text
https://digitalstudio2.github.io/important-notes/share.html#<64-hex-token>
```

- الرمز في `location.hash`، لذلك **لا يُرسل إلى خادم GitHub Pages** في أي طلب HTTP.
- الصفحة تحمل `meta robots="noindex, nofollow, noarchive, nosnippet, noimageindex"`.
- الصفحة تحمل `meta referrer="no-referrer"`.
- العرض يستخدم `textContent` لكل الحقول، فلا تُنفَّذ HTML أو Scripts.
- الحالة لا تعيد الرمز بعد الإنشاء؛ يُعرض مرة واحدة فقط.

### 6.3 الحساب التجريبي

- إخفاء زر سجل النشاط وخيار المشاركة عبر `body.is-demo [data-demo-hide]`.
- حظر إضافي في طبقة البيانات (`demo-restricted`) وفي قاعدة البيانات.
- إعادة تعيين الملاحظات السبع عند الدخول الصريح فقط (`signIn` / `signInDemo`)، وليس عند استعادة الجلسة.

## 8) المخاطر والحدود

1. **رابط المشاركة سرّي:** أي شخص يحصل على الرابط يستطيع قراءة الملاحظة حتى انتهاء الأسبوع أو الإلغاء. لا توجد كلمة مرور إضافية على الرابط. لا تشارك الرابط في أماكن عامة.
2. **اسم المالك:** يظهر الاسم المعروض ولون الصورة فقط، دون البريد أو المعرّفات.
3. **سجل النشاط:** لا يحتوي محتوى الملاحظات، لكنه يحتوي عناوين مختصرة وتصنيفات وتواريخ. يُقرأ عبر RPC محمي بـRLS.
4. **تسجيل الدخول:** يُسجَّل من العميل بعد نجاح المصادقة. إذا أغلق المستخدم الصفحة فوراً فقد لا يُسجَّل الحدث؛ لا يؤثر على الأمان.
5. **الحساب التجريبي مشترك:** أي زائر يستطيع تعديل ملاحظاته السبع؛ لذلك لا تُستخدم لبيانات خاصة.
6. **المفتاح السري وSMTP:** ما زالا بندين يدويين كما في المرحلة 0.
7. **امتيازات `supabase_admin` الافتراضية:** مخاطرة متبقية موثقة، وليست ناتجة عن هذه المرحلة.
